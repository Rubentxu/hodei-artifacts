# Prompt de ejecución para el agente principal

Trabaja en el workspace real de `Rubentxu/hodei-artifacts`, partiendo del árbol y estado remoto actuales. Lee íntegro este directorio, `docs/prd/8-roadmap.md`, las referencias concretas de `TRACEABILITY.md`, y el código productivo afectado antes de planificar cambios. Usa CogniCode para navegar código y REA para observar binarios/protocolos cuando aporte valor, sin considerar sus descripciones como evidencia de paridad.

**Misión duradera:** cerrar secuencialmente H0–H9 con valor entregado consumible, preservando el catálogo de capacidades y añadiendo pasos solo si un bloqueo exige cambios necesarios. No abortes trabajo por backlog no vacío: retoma desde el último hito abierto y investiga bloqueos; si necesitas autorización, secretos o infraestructura externa no disponible, deja `BLOCKED` explícito con un siguiente paso, sin inventar verde ni hacer push sin permisos.

**Política de diseño:** TypeDB 3 como única BBDD principal de conocimiento/metadatos, CAS FS/S3 de blobs, monolito modular Rust, Graph-first, ADTs, funciones `decide/evolve/project`, errores algebraicos, datos verificados e inmutables. Capa de efectos fina: Axum/Tokio, TypeDB, Cedar, HTTP externo, FS/S3, reloj, ID, eventos. Prohibir estados inválidos, null/unwrapped en camino crítico, structs con campos públicos no validados, strings genéricos como IDs y domain service DI hinchado. Puertos por capacidad real, no interfaces por archivo obligatorio. Fronteras y APIs consumibles primero.

**Conserva de Hodei:** `kernel`, IAM, policies, HRN conceptual, infra y VSA donde sean correctos. No compiles los crates de legado al por mayor. Una migración con estrangulamiento (*strangler*) por capacidad resulta preferible a una gran reescritura sin releases.

**Testing:** consultar `Rubentxu/agent-skill/skills/delivery-first-testing/SKILL.md` router y playbooks `ready` `change-impact`, `ephemeral-uat`, `regression-promotion`, `data-driven-design`, `release-assurance`, `merge-assurance`, `harness-economics`, `mutation-guidance` según riesgo. Usar harness base versionado, sesiones UAT/E2E/AAT efímeras en `.sessions/` ignorado o `mktemp`; evidencia externa no sensible y decisión `PROMOTE|REPLACE|RETIRE|DEFER`. Retirar scripts y fixtures efímeros al final de **cada hito**, dejar herramientas y garantías permanentes mínimas. `cargo nextest`/Cargo real, y clientes Maven/Podman/npm/pip reales para contratos de protocolo. Máximo <=15 min en puerta aplicable, y tests de volumen <= código productivo como guardarraíl; no saltar garantía crítica por presupuesto.

**Equipos:** ver `TEAM-PLAN.md`; cada agente trabaja en superficies disjuntas y trae commits o patches revisables. Arquitecto del núcleo firma ontología/ID/eventos y contracts antes del trabajo paralelo que dependa de ellos. Nunca equipos escribiendo `Cargo.toml` raíz, HRN, TypeQL y release simultáneamente.

**Cierre obligatorio de cada hito:** código y tests afectados + 1 a 3 aceptaciones reales efímeras con caso negativo + benchmark cuando aplica; evidencias ligadas a SHA y binario; limpieza comprobada; revisión de ramas/CI; merge en main con árbol limpio, tag/release nuevo sin colisión, assets mínimos reproducibles (binario/distribución, SBOM, SHA256SUMS, manifiesto, changelog) y push remoto real *si está autorizado*. No publicar `sources.zip` como asset. Si no hay permisos, no hacer publicación ficticia: informar `BLOCKED` y entregar producto/local o PR según permiso.

**Regla al terminar:** lee el siguiente TODO no cerrado. Si H0–H9 completos, reportar paridad medida y limitaciones (HA TypeDB CE, protocolos no soportados). No proclamar 100% Nexus CE sin matriz de paridad por formato/versión.

Primera acción: producir el censo desde el árbol actual (no solo documentos), `cargo metadata`, `cargo check --workspace`, `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings` y selección de tests real según herramientas disponibles. Registrar `NOT_RUN` donde falte infraestructura. Abrir H0.
