Tarea HSP-41 — M0/E0.1: la verdad del workspace.

El repositorio arrastraba varias generaciones de codigo y de documentos, y un revisor no podia saber que era real. Este PR produce la verdad del workspace y hace que las pruebas del frontend se ejecuten por primera vez.

## 1. `ARCHITECTURE_STATUS.md`

El documento que manda sobre cualquier otro material de arquitectura:

- **Crates**: cuatro activos (kernel, hodei-iam, hodei-policies, la API) y nueve heredados, con su clasificacion, su tamano y para que sirve cada uno. Los heredados no se borran: son la unica fuente de las ideas de M1, M2, M4 y M9.
- **Capacidades**: cada una con su etiqueta (`implementada`, `experimental`, `planificada`, `legacy`, `deprecada`, `referencia`), su ruta real y la prueba que la demuestra.
- **Documentacion**: que manda, que esta superada y que es material de referencia. Los siete documentos de `docs/arquitectura/` que se llaman "final", "definitiva" o "corregida" y se contradicen entre si quedan clasificados como heredados.
- **Lo que este repositorio NO es**: no hay almacenamiento de blobs, ni OCI/Maven/npm, ni organizaciones ni SCP, ni grafo, ni decision de promocion. El README anterior afirmaba las cuatro cosas.

## 2. El README dice la verdad

Afirmaba un "registry multi-formato", "gestión de organizaciones con SCPs", "WebSockets", un frontend en Vue.js (es React), tests E2E con Playwright (no hay configuracion de Playwright) y despliegue con Docker y Kubernetes (no hay Dockerfile ni manifiestos). Todo retirado o etiquetado.

## 3. Las pruebas del frontend se ejecutan por primera vez

La causa no era solo que faltara el script: **el `.gitignore` del frontend ignoraba `vitest.config.ts` y `src/**/__tests__/`**, de modo que un test nuevo quedaba sin versionar en silencio. El manifiesto tampoco declaraba el corredor de pruebas (vitest, jsdom, testing-library, msw), aunque el lock los traia.

- Se declara el corredor con las versiones que el lock ya traia, y se anaden los scripts `test` y `test:watch`.
- `vitest.config.ts` declara el entorno (jsdom), el fichero de arranque y los alias, replicando `vite.config.ts`: un test que importa `@shared/...` resuelve igual que la aplicacion.
- Se quitan las reglas del `.gitignore` que ocultaban la configuracion y los tests.
- **37 pruebas de componente, en verde, ejecutadas por primera vez.**

## 4. Un carril de CI para el frontend

`npm ci` + `npm test` + `npm run type-check`, en su propio job: necesita otro corredor y falla por otras razones, asi que no se mezcla con las suites de Rust.

## 5. El manifiesto deja de mentir

El comentario "temporarily has stub implementation during policies migration" era falso: la API raiz no es un stub. Y el `exclude` declaraba un solo crate heredado cuando hay nueve. Ahora los nueve estan excluidos de forma explicita, con el motivo.
